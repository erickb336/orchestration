## Problem and outcome

The repository contains only specifications. The user cannot yet see, inspect, or redirect a task through an interface. Outcome: a local web prototype where the user can browse a board of tasks, open a task, read its outcome/approach/options, edit the spec (creating immutable revisions), override the selected option with a reason, configure provider/model per workflow step, and exercise pause/resume/cancel/project-pause against a clearly labeled simulated runtime.

## Scope

Included:

- Vite + React + TypeScript app in this repository (`package.json`, `src/`, `index.html`, config files).
- Pure TypeScript domain module (types, state transitions, revision checks, step model resolution) independent of the UI and of the simulated runtime, so Milestone 2 can move it behind a service.
- Simulated runtime behind a runtime-adapter interface with a capability map; pause requires an acknowledgment that arrives after a delay (or times out on demand).
- Browser `localStorage` persistence for the prototype, labeled as such.
- Unit tests for control semantics and step resolution.
- Generic sample seed data (an example managed project), labeled as sample data. No hardcoded personal paths; managed repositories are user-configured because the tool is intended for public distribution.

Excluded: real Claude/Codex execution, lead conversation, database/service, scheduler, Markdown import/export, any SimpleApps code change.

## Options and tradeoffs

| Option | Approach | User benefit | Effort | Costs and risks | Reversibility |
| --- | --- | --- | --- | --- | --- |
| A | Vite + React + TS SPA; pure domain module + simulated adapter; localStorage | Usable prototype quickly; domain logic reusable in M2 service | Medium | localStorage is not durable truth; must be labeled | High: domain module ports to service unchanged |
| B | Service-first (Node + SQLite) with a thin UI | Durability earlier | High | Delays the review-and-steer loop the spec says to validate first | Medium |
| C | Static HTML mockup without behavior | Fastest | Low | Cannot exercise pause/edit semantics or races; throwaway | High, but little reusable |

## Decision

- Agent recommendation: A
- Selected option: A
- Decided by: Lead
- Rationale and evidence: PROJECT_SPEC.md milestone table puts the interactive prototype first and the durable service second; keeping transitions in a pure module lets Milestone 2 reuse them and its tests.
- Uncertainty and what would change the decision: if the user wants persistence across browsers/devices immediately, pull the SQLite service forward (option B).
- User override, if any: none

## Acceptance and validation

- Every screen shows that execution is simulated; no UI text claims live execution.
- Board: list (default) and board view grouped by Proposed, Ready, Running, Reviewing, Paused, Blocked, Done; cancelled in history. Filters: area, status, role, provider, changed since last visit. Sort: priority, latest activity. Cards show title, benefit, priority, state, role/provider, latest activity, approach summary, and a new-decision badge.
- Task detail shows outcome and chosen approach first, then options, decision (recommendation separate from selection, override reason preserved), acceptance, steps, activity, and revision history with a diff between any two revisions.
- Editing a spec creates a new immutable revision; editing a paused task keeps its hold; editing running work stops it (Pausing → acknowledged) before the new revision can run, and results from the old revision are discarded, not integrated.
- Pausing running work shows Pausing until the simulated runtime acknowledges; an injected acknowledgment timeout shows a visible control failure.
- Project pause freezes dispatch, pauses all running steps; project resume preserves individual task holds.
- Steps: per-step provider/model with Inherited/Pinned indicator and Reset to default; resolution order step → task role override → project role default → project default; changing a role default updates unpinned, undispatched steps only; dispatched attempts keep their snapshot.
- Checks: `npm run typecheck`, `npm test`, `npm run build`; manual browser pass in light and dark appearance.
