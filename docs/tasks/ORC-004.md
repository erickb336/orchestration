## Problem and outcome

The service drives only a fake runtime. PROJECT_SPEC.md's Milestone 3 exit is: run Claude and Codex workers concurrently, and pause and resume each worker and the whole project, with saved evidence.

Outcome:

- **Opt-in real mode:** the service can run real Claude (Agent SDK) and Codex (app-server) workers against a user-configured git repository.
- **Workspaces:** each attempt runs in its own git worktree.
- **Shared context:** workers receive the same versioned assignment envelope, and report declared outputs in a checked format.
- **Controls:** pause, resume, and project pause reach both providers, and "Paused" appears only after the runtime confirms the stop.
- **Evidence:** a scripted real-run test records what actually happened.

## Scope

Included:

- **Adapter contract:** a common `RuntimeAdapter` contract (`server/runtimes/types.ts`) with asynchronous events, health, a model catalog, interrupt with confirmation, hard kill, and a capability map. The fake runtime is ported to the contract.
- **Claude adapter:** built on the pinned `@anthropic-ai/claude-agent-sdk`.
  - Settings and CLAUDE.md files are not loaded (`settingSources: []`), native subagents are disabled, and tools are allowlisted by role.
  - Interrupt with confirmation (stream end); after a timeout it escalates to aborting the process.
  - Authentication is `ANTHROPIC_API_KEY` or cloud-provider credentials. A Claude.ai subscription is not supported, per Anthropic policy.
- **Codex adapter:** built on the pinned `@openai/codex` app-server over JSON-RPC stdio.
  - Approval policy `never`, a workspace-write sandbox restricted to the worktree with network off, and `agents.enabled=false`.
  - `turn/interrupt` is confirmed by `turn/completed: interrupted`, with a kill as the fallback.
  - The model list comes from `model/list`. Authentication is whatever the local Codex has (ChatGPT login or API key).
- **Workspaces** (`server/workspaces.ts`):
  - Writer roles run in a new branch worktree based on their input change (or the repository's HEAD). Other roles run in a detached, read-only-by-policy worktree.
  - Worktrees live in the Orchestrator data directory, never inside the managed repository.
  - After a writer finishes, the service commits its changes. The commit SHA and diffstat become the `code-change` artifact.
- **Assignment envelope** (`server/envelope.ts`): the role brief, vision, spec and selected option, acceptance, step instruction, and input artifacts with refs, followed by an output contract. The worker ends with a JSON block giving a summary per declared output, plus `openFindings` for reviews.
- **Service wiring:**
  - `ORCHESTRATION_RUNTIME=fake|real` (default `fake`). Real mode requires a configured git repository.
  - Provider health is shown in the UI. A step whose provider is not ready is blocked with an explanation and never switched to another provider.
- **Domain:**
  - Artifacts gain an optional `ref`.
  - Attempts gain `activity`, `usage`, and `actualModel`.
  - New commands: `initProject` (an empty real project) and `createTask` (a user-authored task from a template).
- **UI:**
  - The execution banner is truthful per mode: "LIVE EXECUTION" versus "SIMULATED".
  - Settings gains provider health and a project setup form. Runs show their activity, usage, and actual model.
- **Real-run test:** `scripts/real-run-test.mjs` creates a throwaway git repository and a fresh database, and runs concurrent Claude and Codex steps under tight limits. It pauses and resumes each worker and the project, and writes an evidence JSON file. The user runs it with their credentials.

Excluded, and moved to the next milestone:

- The lead conversation and agent-created tasks. PROJECT_SPEC.md lists the lead conversation under Milestone 3, but it depends on a real lead run with board tools, which is Milestone 4 work. This is recorded as a deliberate deviation.
- Merging into the managed repository's branches. Results stay on `orchestration/*` branches for the user to merge.
- Claude.ai subscription authentication.

## Options and tradeoffs

| Option | Approach | User benefit | Effort | Costs and risks | Reversibility |
| --- | --- | --- | --- | --- | --- |
| A | Claude Agent SDK and Codex app-server adapters behind one async contract; service-owned worktrees and commits | Real interrupt confirmation on Codex, stream-end confirmation on Claude, live steering available later, and model listing for Codex | Large | The Codex app-server is experimental, so the version is pinned and the schema generated. Claude requires an API key. | High: each adapter is isolated behind the contract |
| B | CLI one-shot processes (`claude -p`, `codex exec --json`) killed by signal | Simplest | Medium | No graceful interrupt, steering, or model list; a pause becomes a kill | High |
| C | Codex TypeScript SDK plus Claude SDK | Official SDKs for both | Medium | The Codex SDK wraps `exec`: no steering, and its interrupt is a SIGTERM kill | High |

## Decision

- Agent recommendation: A
- Selected option: A
- Decided by: Lead. The user decided authentication ("whatever works best locally") and verification ("build now, you run the real test").
- Rationale and evidence: only option A gives both providers a confirmed interrupt path, which PROJECT_SPEC.md requires ("never implement pause as a visual status change alone"). See `docs/research/runtime-adapters.md`.
- Uncertainty and what would change the decision: the app-server is experimental. If the pinned version's schema or behaviour disagrees with the documentation, the adapter follows the generated schema, and the capability map marks anything unverified. A real-run failure could push Codex to `exec --json`, which would mark interrupt as kill-only.
- User override, if any: none

## Acceptance and validation

- Adapter unit tests cover both adapters against scripted fakes: the SDK stream for Claude, and a JSON-RPC stub process for Codex. They cover start, events, completion with outputs, interrupt with confirmation, interrupt timeout then kill, failure, and health.
- Scheduler tests using async adapter events cover: concurrent runs on two providers, one active attempt per step, stop confirmation, orphan handling, and events arriving after a lease change.
- Workspace tests on a temporary git repository cover: worktree creation for writers and readers, the commit becoming a `code-change` artifact with a SHA, and no writes inside the managed repository's working tree.
- Envelope and output-parsing tests: a missing or malformed output block leads to the existing failed/blocked path.
- The UI never shows "Paused" before the adapter confirms the stop. Real mode shows the live banner, and a provider that is not ready shows as blocked with guidance.
- The real-run test (run by the user) records concurrent Claude and Codex runs, a per-provider pause and resume, and a project pause with timestamps and outcomes.
- Checks: `npm run typecheck`, `npm test`, `npm run build`, and a browser pass in fake mode.

## Revision history

- r1, Lead, 2026-09-29: initial spec. Authentication and verification choices come from the user.
- r2, Lead, 2026-09-29: decisions from integration.
  - Codex workers run isolated from the user's own Codex setup, for parity with Claude workers:
    - plugins, apps, computer use, browser use, the in-app browser, and memories are disabled;
    - web search is disabled;
    - each MCP server still enabled is disabled by name;
    - the isolation fails closed if MCP servers cannot be enumerated.
  - A stop the scheduler did not request (for example a time limit) fails the step instead of requeueing it.
  - Real mode starts from an empty project: sample tasks never reach real agents.
  - The scheduler dispatches nothing until an absolute path to a usable repository is configured.
  - New projects default to "auto" models on each provider.
  - `ORCHESTRATION_RUNTIME` selects the fake or real runtime; fake stays the default.
- r3, User direction, 2026-09-29: workers may use the local setup.
  - The user said: "since it is local", workers may use the local Claude/Codex setup and its MCP servers, and they want connections such as Cloudflare, Vercel, and AWS available.
  - Each provider gets a worker environment setting:
    - "Isolated" (the default): no user settings, plugins, or web tools; only the MCP connections the user selects from their own configuration.
    - "Use my local setup": the user's own settings, plugins, and all MCP servers.
  - Both environments keep file edits inside the worktree, disable native sub-agents, and keep network access off for Codex commands.
  - Each run records its environment and connections in the snapshot.
  - Isolated Codex runs fail closed if the user's MCP servers cannot be enumerated. Local runs do not need that check.
  - Running CLIs such as `vercel` or `aws` directly would need shell access and command network access. That is not included yet.

  - Real-mode UI: project setup, New task held before start, and model resolution against the real catalogs. No runs were dispatched.
- **Independent review (S5) findings and resolution:**
  - **High:**
    - *The service's git ran agent-controlled code* (hooks, fsmonitor, a case-variant `.GIT` gitlink). Fixed:
      - All service git calls disable hooks and fsmonitor, strip `GIT_*` from the environment, and use the recorded git directory explicitly.
      - A tampered `.git` file refuses the commit, and the run fails.
      - The Claude guard rejects `.git` in any letter case.
      - Regression tests cover a planted hook and gitdir redirection.
    - *A malformed output block could wedge a run in "running".* Fixed:
      - The parser accepts only an object root and tolerates code fences inside summaries.
      - Events are applied one at a time and requeued if their transaction fails.
      - A run whose process has gone without a result is marked lost.
      - Regression tests added.
  - **Medium:**
    - *Codex writers could write shared temp directories.* Fixed: `/tmp` and `$TMPDIR` are excluded, each run gets a private temp directory beside its worktree, and the test data moved out of the system temp directory.
    - *Codex reads are not restricted to the worktree.* Not fixable with the pinned sandbox API without real verification. The limitation is stated in Settings and the README.
    - *A sample database could send sample tasks to real agents.* Fixed: a sample flag blocks real dispatch, and a regression test was added. Project ids also namespace branches and worktrees.
    - *The real-run test could pass without evidence.* Fixed: nine explicit checks, all required.
    - *Local mode loaded the worktree's own Claude project settings, whose hooks could run.* Fixed: only user-level settings are loaded. The UI also states that MCP servers and plugins run unsandboxed with the user's permissions.
  - **Low:**
    - Connection-list race: fixed (cached).
    - Catalogs re-sync on each health refresh.
    - The Auto routing wording was corrected.
    - The UI states that turn limits apply only to Claude.
    - Repository checks are cached.
- **Limitations and pending items:**
  - Worktrees and `orchestration/*` branches are not pruned yet.
  - A reported "killed" stop can precede the confirmed exit of the process.
  - **The real concurrent Claude and Codex run (the Milestone 3 exit) needs `ANTHROPIC_API_KEY`: `node scripts/real-run-test.mjs`.**
