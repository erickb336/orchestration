## Problem and outcome

State lives in one browser's local storage, the simulation runs inside a tab, and nothing survives outside that tab. PROJECT_SPEC.md requires a durable store, transactional controls with expected-revision checks, idempotent commands, a single scheduler lease, and reconciliation after restart without duplicate or falsely completed runs.

Outcome: a local TypeScript service owns state in SQLite and serves the UI. Every change is a validated command applied in a transaction. One scheduler holds a renewable lease and drives a fake runtime through the runtime adapter boundary. After a restart, the service reconciles instead of redispatching blindly. The UI becomes a client that truthfully shows when the service is offline.

## Scope

Included:

- `server/`: SQLite store (Node's built-in `node:sqlite`, no native dependency), command handler, HTTP API bound to loopback with host/origin/header protection, SSE change stream, static UI serving, scheduler with lease, fake runtime adapter, startup reconciliation.
- `src/domain/commands.ts`: the shared, typed command registry mapping command names to pure domain operations.
- A new attempt outcome, `lost`, for runs whose process no longer exists after a restart.
- UI switched from local domain calls to service commands; offline banner; simulation controls moved to the service.
- `npm run dev` (service and UI together) and `npm start` (build, then serve) for local installs.
- Tests: restart persistence, idempotency, stale writes, lease exclusivity and expiry, restart reconciliation without duplicates or false completion, pause/stop acknowledgment through the fake runtime, pause/completion ordering, HTTP origin protection.

Excluded: real Claude/Codex adapters (Milestone 3), lead conversation, Markdown import/export, multi-project UI, notifications, packaging as a global CLI.

## Options and tradeoffs

| Option | Approach | User benefit | Effort | Costs and risks | Reversibility |
| --- | --- | --- | --- | --- | --- |
| A | SQLite with an authoritative state document per project, an append-only command log with idempotency keys, a mirrored event table, and a lease table; all writes in `BEGIN IMMEDIATE` transactions | Reuses the tested pure domain unchanged; strong transactional semantics; small | Medium | Whole-document writes grow with history; ad hoc queries need the event table or a later projection | High: tables can be normalized later from the document and command log |
| B | Fully normalized tables (tasks, spec revisions, steps, attempts, artifacts…) with repository code per entity | Queryable, row-level writes | Large | Duplicates domain logic in SQL mapping; high risk of drift from the tested transitions | Medium |
| C | JSON file on disk with a lock file | Simplest | Small | No transactions, fragile under crashes and concurrent writers; fails the spec's consistency requirements | High |

## Decision

- Agent recommendation: A
- Selected option: A
- Decided by: Lead
- Rationale and evidence: the domain is already pure `(state, command) → state` with serialized race semantics and 46 tests. Option A makes it durable and transactional without rewriting it, and it satisfies expected-revision checks, idempotency keys, and the lease. The command log keeps a full audit of user and lead intent.
- Uncertainty and what would change the decision: if histories grow large enough that whole-document writes become slow (unlikely for a single local project), add normalized projections for events and artifacts.
- User override, if any: none

## Acceptance and validation

- State persists across service restarts; the UI reloads it from the service.
- Each command runs in one transaction. A repeated idempotency key returns the original result without applying it twice. Stale spec, pipeline, vision, and template edits return 409, and the UI keeps the user's draft.
- Only one scheduler holds the lease. A second instance on the same database observes only. An expired lease is taken over, followed by reconciliation.
- After a restart: runs that were running become `lost` with a checkpoint note, runs that were stopping are acknowledged as stopped, nothing is marked completed, and at most one active attempt exists per step at all times.
- Pause reaches the fake runtime through the adapter. Paused is shown only after acknowledgment, and an unresponsive runtime produces a control failure.
- The API binds to 127.0.0.1 and rejects foreign `Host` headers, cross-origin browser requests, and requests without the client header.
- When the service stops, the UI shows it as offline, disables controls, and keeps showing the last known state as stale.
- Checks: `npm run typecheck`, `npm test`, `npm run build`, a browser pass through the service, and a manual restart with an active run.

- Fixed interfaces: the command registry in `src/domain/commands.ts` and this HTTP contract:
  - `GET /api/state` returns `{ version, state, service }`.
  - `GET /api/stream` is Server-Sent Events: `event: state` with the same payload on every change.
  - `POST /api/commands` takes `{ name, args, idempotencyKey }` and returns `200 { version, result }`, or `409 { error, kind: "stale" }` / `400 { error, kind: "control" | "invalid" }`.
  - `POST /api/sim` takes `{ auto?, ackMode? }`. `POST /api/sim/step` advances the fake runtime once. `POST /api/sim/reset` restores the sample project.
  - All POSTs require `Content-Type: application/json` and `X-Orchestration-Client: 1`.
- Recovery: the service stores its database at `~/.orchestration/orchestration.db` (override with `ORCHESTRATION_DB`). Deleting it restores sample data. Revert the branch to roll back.

  - `npm run build` succeeds.
  - Mutation check: removing the reset-id fix fails its regression test.
- **Manual evidence:**
  - Crash smoke test with `kill -9`: an idempotent retry returned the same version. During the lease window the new instance only observed. After the lease expired, the stopping run became `stopped`, running runs became `lost` and were redispatched as new attempts, the hold was preserved, and nothing was marked completed.
  - Browser, full stack through the Vite proxy:
    - Pause showed "Pausing" and then "Paused" after the fake runtime acknowledged.
    - A spec edit from a second client arrived over the stream. The open editor kept its draft, showed a diff, and blocked saving.
    - Killing the service produced the offline banner after 12.3 s, with controls disabled. After a restart the UI reconnected automatically and showed the lost runs and their fresh attempts.
    - Cross-origin reads returned 403 and same-origin reads returned 200.
- **Integration findings, fixed:**
  - The tsx CLI wrapper left an orphaned service holding the port and lease after its parent was killed.
  - SSE through the Vite proxy never errored when the service died, so the UI stayed "online".
- **Independent review (S4) findings and resolution:**
  - **High:**
    - A reset from another instance let old processes report into new runs (reused ids). Fixed: ids are monotonic, and local processes whose run is no longer active are killed. Regression test added and mutation-checked.
    - A failed reconciliation was never retried. Fixed: the scheduler activates only after reconciliation commits, and on failure releases the lease. Regression test added.
    - An unreadable static file crashed the process. Fixed: stream errors are handled, and uncaught exceptions shut down cleanly. Regression test added.
  - **Medium:**
    - During development, other localhost pages could read state through Vite's CORS. Fixed: `cors: false`, and the service rejects foreign Origin or cross-site fetches on every `/api` request.
    - Scheduler writes were not lease-checked. Fixed: the lease is checked inside each transaction, only runs dispatched in the current cycle are started, and the lease is 15 s against a 5 s busy timeout. Regression test added.
    - The event mirror went stale after a reset. Fixed.
    - A database in a newer format was silently overwritten. Fixed: it is refused. Regression test added.
  - **Low:**
    - An idempotency key reused for a different command is rejected.
    - A null body or a malformed path returns 400.
    - Symlinks are contained within the static root.
    - A Node version check runs before `node:sqlite` loads.
    - The Vite proxy follows `ORCHESTRATION_PORT`.
    - The dev script stops both processes if either exits.
    - SIGHUP is handled, and the lease is released on server errors.
- **Limitations:**
  - The runtime is fake. Real Claude and Codex adapters arrive in Milestone 3.
  - Each click generates a new idempotency key, so retrying after a lost response can apply a command twice. Edits are still protected by revision checks; `createFollowUp` could create a duplicate task.
  - The state is stored as a single document, which is fine for a single local project.
  - Not tested: Windows, and laptop sleep or clock jumps.
