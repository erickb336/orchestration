## Problem and outcome

**The problem.** Today you talk to the lead only on the web page. You also want:

- to start the engine and talk to the lead from the tools you already use;
- to keep several projects apart, each with its own lead. For example, one engine improving Orchestrator and another building your apps;
- to check in from your phone while you are out.

**The outcome.** A Claude Code plugin and a local MCP server let you talk to the lead of the repository you are in. The conversation is about **features you can try end to end**, not code.

**From the phone.** Claude Code's Remote Control (generally available) lets you continue the session on your Mac from the Claude app. Plugin commands and MCP tools work there, and push notifications arrive. So no Tailscale, no open port, and no Discord bot of our own are needed. Anthropic's Discord, Telegram and iMessage channel plugins (research preview) can message the same session.

## Scope (high level)

The UX is in [docs/design/ORC-023-ux.md](../design/ORC-023-ux.md).

- **A local MCP server.** It reaches the engine's API on 127.0.0.1, and starts the engine if needed.
- **A Claude Code plugin.** It has a few `/orchestrator:*` commands, plus a skill that keeps Claude a relay: one lead; the lead's reply shown word for word.
- **A project registry** (`~/.orchestration/projects.json`). It holds one engine per project, with its own data folder and port. The repository you are in picks the engine.
- **Decided by the owner (2026-10-01):**
  - **Waiting for the lead:** the command waits for the reply, then moves to background tasks after 2 minutes.
  - **Status questions:** Claude answers them from the engine's record, with no lead run.
  - **"Needs you" decisions:** allowed from chat on your explicit word. Merges and cancels also show Claude Code's permission prompt.
- **Open:**
  - The command shape. The draft is feature-first: `:lead`, `:status`, `:show`, `:try` and `:needs`.
  - What the engine adds for "features, not code": starting a task from chat, with Undo; acceptance scenarios with a verified state; evidence per scenario, through a verification recipe; and "try it".

**Excluded:**

- Codex packaging. The MCP server stays provider-neutral.
- Our own Discord bridge.
- A custom terminal chat.
