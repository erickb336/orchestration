# ORC-031: Agents may start their own subagents, tracked

## Task identity

- **ID and title:** ORC-031. Let a run's agent use its provider's own subagents (Claude's Agent tool, Codex's multi-agent). Each subagent is counted, costed, capped and shown, and the feature is switched on for a provider only after real runs prove pause, cost and safety for it.
- **Author and timestamps:** Lead (Claude), 2026-10-02.
- **Status, priority, and priority rationale:** **Planned, not started; P1.**
  - The owner asked "Are we also tracking how many agents our 'role'/named agents launch? … a single claude session can launch sub tasks as agents".
  - On hearing that they are switched off, they said "I kinda want to allow it - convince me otherwise - why not", then "Can we allow that and track it?".
  - Recommended order: after ORC-029, before ORC-030, so ORC-030's QA covers it.
- **Specification revision:** 1.
- **Project vision revision:** PROJECT_SPEC.md and PRODUCT.md as of 2026-10-02.

## Problem and outcome

**Today.** Every named agent (the lead, a coder, a reviewer, the PE, the designer) is exactly one model session, and each provider's own subagents are switched off at every start:

- **Claude:**
  - the `Agent` and `Task` tools are removed from every session;
  - the workspace guard refuses them;
  - a session that still lists one leaves a warning in the service log.

  Tests: `server/runtimes/claude.test.ts`.
- **Codex:**
  - `agents.enabled=false` and `--disable multi_agent` are set on every app-server start, including the local-setup mode;
  - a sub-agent item that appears anyway becomes an activity note, "not tracked".

  Test: `server/runtimes/codex.test.ts`.
- **Parallel work goes through Orchestrator,** as separate runs it dispatches, counts against "Agents at once", pauses and budgets. A Goal's child tasks are one example.

**The problem.** Big steps could go faster if an agent fanned out its own searches and drafts. And when a subagent does slip through, it is a log line, never counted or shown.

**What allowing them puts at risk.** Every guarantee Orchestrator makes is per run, and a subagent lives inside its parent's run. For each provider, these are unproven:

1. **Pause:** does interrupting the parent stop its subagents? Truthful pause is a hard rule (AGENTS.md).
2. **Cost:** does the parent's reported usage include the subagents'? Claude's reported total probably does. Codex's sub-threads may report usage separately. If they do, the budgets (ORC-029) would undercount.
3. **Safety:** do Claude's workspace guard and Codex's sandbox apply to subagents too?
4. **Limits:** "Agents at once" no longer bounds the model sessions, and the plans' usage limits drain faster.

**The outcome.**

- **Agents may start subagents where the owner allows it,** per role and per step (AGENTS.md: model and provider choices are per step).
- **Every subagent is recorded on its run:** when it started and ended, what it was asked, its model, its usage and how it ended. The run shows how many, the most at once, and their cost.
- **A cap per run,** enforced where the provider allows it.
- **A provider's switch is enabled only after real runs prove the four points above for it.** The capability map's `childAgentTracking` goes from "unsupported" to "supported" for that provider only with that evidence.
- **Until then, any subagent that slips through is counted, shown and listed under Needs you,** instead of left as a log line.

## Scope

- **Claude:**
  - Remove `Agent` and `Task` from the disallowed list when allowed. They stay disallowed otherwise.
  - Count subagents from the `Agent` tool calls and the messages tagged with `parent_tool_use_id`.
  - Enforce the cap in the PreToolUse hook: refuse an `Agent` call over the cap with a clear reason.
  - Check that the hook and the workspace guard also run for the subagents' own tool calls.
  - Cost: the session's reported total and its per-model breakdown.
- **Codex:**
  - Drop `agents.enabled=false` and `--disable multi_agent` when allowed.
  - Count from `collabAgentToolCall` items and the sub-threads' notifications.
  - Find out whether the sub-threads' token usage is included in the parent's or reported separately, and sum it accordingly.
  - Find out whether Codex can cap the number of agents (a config key) and whether `turn/interrupt` stops sub-threads.
  - If no cap exists, Codex's switch stays off.
- **The domain:**
  - Each run's record gains its subagents: count, the most at once, items, and cost.
  - The budgets count their cost.
  - "Agents at once" keeps counting runs, and the UI shows subagents separately.
- **Settings:** "Let agents start helpers", per role, with a per-step override and a cap per run. It is off until the provider is verified.
- **Notes (ORC-022)** go to the parent agent. Subagents do not receive notes, and the UI says so.
- **Principles** go to the parent. Whether a subagent receives them depends on what the parent writes into its prompt; the parent's brief asks it to pass on the relevant ones.

**Excluded:** subagents across providers (a Claude parent starting a Codex helper). Orchestrator's own runs remain the way to mix providers.

## Options and tradeoffs

| Option | Approach | Benefit | Costs and risks |
| --- | --- | --- | --- |
| **A (recommended)** | Allow per role and step, with tracking and caps; enable each provider only after real runs prove pause, cost and safety | Faster big steps without losing Orchestrator's guarantees | Verification runs cost usage; Codex may stay off if it cannot be capped or paused |
| B | Allow everywhere now, with tracking | Fastest to ship | Pause, budgets or the sandbox could silently stop being true |
| C | Keep them off, but count any that slip through | Simplest and safest | Gives up the speed the owner wants |

## Acceptance and validation

- **Tests, with scripted sessions that start subagents:** counting, the cap refusal, cost attribution, and the Needs-you item for a subagent where none is allowed.
- **Real runs, with the owner's consent and budget,** per provider. Each must show:
  - subagents counted and their cost in the total;
  - a pause that stops them, confirmed;
  - a subagent's attempt to write outside the worktree is refused.

  The records go in `docs/real-runs/`.
- The README and the capability map say exactly which provider is verified.
