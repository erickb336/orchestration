# ORC-030 stabilization, worker S1: the budgets and the PE

**What this is.** The design choices for four rows of the ORC-030 backlog (`docs/design/ORC-030-stabilization.md`): B-02 with decision D-3, B-03, B-06 and B-18. Each section gives the defect, its root, the options, the choice and the test that failed first.

**Where it fits.** ORC-030 step 2 fixes the backlog at the root. These four rows are about money and the PE: the building budget's stop, the PE's estimates, and the PE's review in the studio.

## B-02 and D-3: a paused Codex run stopped the factory

**The defect.** Every real Codex run that was paused recorded no usage (10 of 10 in `docs/real-runs/`, for example run-1038 and run-1046). The budget rule "unknown is never zero" counts a run with no recorded cost at its run limit. Codex has no run limit, so while a building budget was set, one ordinary pause held every new run. A model missing from the price table did the same.

**What the Codex adapter knows.** Codex sends `thread/tokenUsage/updated` after each model request completes, with the thread's totals. It sends nothing for a request that is cut off: an interrupt, a failure or a crash. So at the end of a run the adapter knows exactly:
- the totals of the requests that completed;
- whether it asked Codex for the turn at all (before that, no model request was made);
- whether the turn completed (if not, the last request has no report).

The adapter already passed its totals with a stop. A run paused in its first request had none, so it reported nothing, and "nothing" looked the same as a run the service lost.

**The root.** Design. The domain could not tell three different facts apart: "no model request", "one request with no report", and "no record at all". It treated all three as a cost with no bound.

**Options.**

| Option | What it does | Why not, or why |
| --- | --- | --- |
| a. Record the partial usage the adapter saw | The adapter reports its totals with the stop. | Already done. It does not help when no request completed, which is the observed case. |
| b. No model call is $0; a cut-off request counts at an estimate | The adapter reports zeros, and marks a cut-off request (`openRequest`). The budgets count that request at an estimate, labelled as one. | **Chosen.** It removes the root: each case has its own record, and only a cost nothing bounds still holds the stop. |
| c. The owner acknowledges the "no recorded cost" item (D-3) | A chip stays on the budget; the item comes back for a new unpriced model. | It hides the item but keeps the stop, and a new paused run would bring it back each time. |
| d. Give Codex runs a spend limit that the service enforces | The service stops a Codex run past the run limit, so an unknown run counts at the limit. | A product change (Codex runs would stop at $2), and it does not help a model with no price. |
| e. Ask Codex for the thread's usage (`account/usage/read` with a thread id) | Codex's own estimate of the thread. | Unverified: it needs a real run, and it may exist only for some accounts. |

**The choice (b), as built.**
- The Codex adapter reports usage at every end it reports: its totals, or zeros when no request completed. When the run ends before its turn completed, the usage has `openRequest: true`. A run that never asked for its turn reports zeros: it made no model request, a known $0.
- No tokens cost $0 at any price.
- Each cost with no full record counts at an estimate, never $0:
  - a cut-off request: the dearest finished run on the same model so far (a whole run has at least one whole request), or the run limit before there is one;
  - a model with no price: its tokens at the dearest price its provider has in the price list;
  - a Claude run with no usage: its run limit, its spend cap, as before.
- A cost that nothing bounds (a Codex run the service lost, or from before this fix) still holds the stop, and the stop names the run.
- The PE's budget check uses the same counted spend, so a pause no longer sends every PE call with a building cost to the owner.

**D-3.** With (b), nothing waits for the owner when every cost is counted. So the separate "no recorded cost" item in Needs you is removed, and nothing needs an acknowledgement. The budget's words (the floor, Settings and the Lock in summary) say what is estimated and why. When a cost cannot be counted, the stop is the one item, and its detail names the runs.

**What stays imperfect.** The estimate for a cut-off request is high on purpose: a whole run, not a part of one. A model with no price can cost more than the dearest known price. Both are labelled as estimates.

**Tests that failed first.** `server/runtimes/codex.test.ts` (8 tests: the stop's usage, the open request, the crash, no request before the turn) and `src/domain/spend.test.ts` ("costs the providers do not report", 8 tests, among them the real run's pause and the PE's budget check).
